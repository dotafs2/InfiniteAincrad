# Skin collection expansion

The collection now contains 27 Classic and 17 Special forms, matching the observed reference collection capacity. All 44 entries build real meshes. The ten existing IDs retain their legacy migration thresholds, roles and skills; Core Shell deliberately changes to the requested blue color in both its definition and its actual accretion shader. New entries use a legacy score above the old maximum, so loading an old best-round score does not silently grant 34 skins.

The 22 new Classic forms have distinct food and animal silhouettes: egg, doughnut, strawberry, citrus, watermelon, pretzel, popcorn, pizza, cookie, waffle, pancake, bacon, chocolate, cake, pineapple, crab, fox, rabbit, frog, owl, turtle and snail. The 12 new Special forms use a winding key, crown, satellite, carnival roof, rocket, rainbow, thundercloud, dragon wings, jellyfish tentacles, crescent and stars, coral branches, and speakers with notes. The designs and meshes are authored in code. They are not licensed reference-game assets or color swaps of one model.

The five established Special abilities are unchanged. The 12 new Special forms are cosmetic and say so in their play descriptions; Special denotes a collection category, not a promise of a new gameplay ability. Nothing in the new geometry owns a collider or changes the opening size, swallowing rules, speed or boost.

The shared base ring and explicit additional geometry stay within the established player budget of 18 mesh instances and 4,500 triangles per skin. The new suite builds each actual form, projects all visible geometry through the real 144 by 106 thumbnail camera, enforces a four-pixel safe margin, tests duplicate IDs and color-independent geometry fingerprints, verifies migration guards, checks the blue shader parameter and confirms advancing preview clocks. The final run passed 991 assertions with no failures; the report and source hashes are retained in artifacts/fixes-20260928/skins.

Independent review is required before release. The suite does not establish that these primitives look as polished as the reference game, certify browser screenshots, or measure phone GPU performance. The parent task integrates the catalog into game.gd, collection paging, descriptions and active preview updates, then runs the release gate.

A subsequent rendering-oriented self-audit caught cap triangle winding opposite Godot's clockwise front-face convention. Polygon perimeters are now normalized before deriving side normals, cap triangles use the proper winding, and the acceptance suite checks every authored polygon triangle against its outward normal. This fix is included in the final evidence and requires independent reviewer verification.
