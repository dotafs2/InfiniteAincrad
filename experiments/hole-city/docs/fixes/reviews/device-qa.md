# Independent review: opt-in device QA

Status: PASS for recorder isolation, state accounting, bounded memory and release injection after two review corrections. Reviewer: expand_skin_catalog; implementation author: root.

The first review found that release injection checked the engine-construction anchor but did not check the recorder script anchor. A changed export template could therefore silently skip the recorder and fail to activate test-mode isolation for a QA URL. The author extracted install_device_qa and now rejects missing, duplicate or already-installed anchors before rewriting the HTML. The second finding was an unbounded visibility-event array while recording remained paused or hidden. Trace and visibility events are now each capped at 3,000 and exported omission counts disclose incomplete telemetry.

The independent Python injection review passes 17 assertions using disposable synthetic HTML, package and wasm files. It covers missing and duplicate anchors, rejecting partial rewrites, script order, test flags before Engine construction, exact embedded package/wasm/recorder hashes, preserving binary contents and hashing the final injected HTML. These fixtures are explicitly synthetic; final exported artifact matching remains a release-gate check.

The independent Node VM review passes 19 assertions. Six ordinary/invalid opt-in URLs touch neither DOM nor animation clock. The actual injected hook leaves ordinary arguments intact and supplies --test and --device-qa only when enabled. The enabled flag exists before DOMContentLoaded, so save isolation is ready before engine construction. The UI mounts afterward. A stress fixture records 6,001 state updates and 5,009 visibility events: storage remains capped and omitted counts are exact. Pause/hidden/map-transition gaps are excluded, a visible 50 ms stall remains in food samples, device identity stays unspecified when absent, context loss is retained, and the JSON carries the exact inserted hashes. The author's separate 12-check recorder suite was also rerun independently, including its 72,000-frame cap.

Source inspection confirms game.gd skips loading actual progress in test mode and only creates the bridge with both test and device-QA arguments. The bridge uses PROCESS_MODE_ALWAYS so pause transitions are delivered; headless execution disables it. Test progress has no file path unless a test explicitly supplies one. Ordinary visits install no recorder owner or callback. Recording performs one constant-cost append per sampled frame, capped periodic 120-sample summary sorts, two telemetry bridge updates per second or state changes, and bounded arrays. The download uses a local Blob, with no network upload. Release artifact hashes are collected after injection and checked again after copying to the preview.

The recorder measures browser requestAnimationFrame cadence, including presentation stalls. It is not a direct GPU timer and does not prove an iPhone 14, thermal stability, visual correctness or 60 FPS. The exported report expressly refuses automatic phone acceptance. No browser, CDP connection, user save or foreground app was used during this review.
