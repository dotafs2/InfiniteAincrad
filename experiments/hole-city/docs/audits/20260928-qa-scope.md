# QA scope review — v0.7.0

This review accompanies the user-requested three-agent comparison. It changes
no game runtime, project settings, saved progress, preview bundle or server.

## Confirmed acceptance gaps

1. **No browser or iPhone 14 frame-time gate.** `tools/release_web.py:103`
   runs native Godot headlessly. `:122` loads the exported PCK into that same
   native headless executable; it does not execute the WebAssembly build in a
   browser. The 5,285 source and 5,285 package assertions verify the stated
   logic/assets, not phone rendering, shader appearance, heat or sustained FPS.
   `tests/performance_acceptance.gd:99` checks collision/query/batch parity and
   does not assert a frame budget. Prior isolated CPU timings are explicitly
   headless Mac measurements in `docs/performance-20260928.md`.

   Acceptance: an actual iPhone 14 capture of both maps from opening through
   repeated large collapses, recording frame times, thermal stability, input
   latency, graphics settings and the exact build hash. A target of sustained
   60 FPS requires evidence including GPU work, not a 60 Hz simulation flag.

2. **NPC movement assertions miss facing and separation.**
   `tests/mobile_maps_acceptance.gd:47` manually steps pedestrian movement at
   0.1 seconds, while gameplay normally uses much smaller frame steps. It
   checks sidewalk containment and vehicle spacing, but not pedestrian
   heading versus velocity or pedestrian overlap. The city audit reproduced
   a frame-rate-dependent heading defect despite this gate passing.

   Acceptance: compare actual displacement and forward direction at 30, 60
   and 120 Hz, including slow walking; track pairwise occupied capsule space
   under ordinary, chase and fleeing routes. Include visual bone/foot review.

3. **New collection input checks use mouse events.**
   `tests/ui_redesign_acceptance.gd:17` and
   `tests/coin_skins_acceptance.gd:20` exercise real viewport routing, but
   construct mouse motion and mouse buttons. They establish mouse navigation
   and logical hit areas, not native touch event parity or browser safe areas.
   Existing `tests/portrait_acceptance.gd:11` does use screen touch and drag
   for gameplay, but that suite is absent from the 16-suite release list.

   This audit reran the existing portrait suite with `--test --fixed-fps 60`:
   **30 checks pass**. Its JSON is in
   `artifacts/reference-audit-20260928/qa/portrait.json`. The run confirms
   current simulated touch movement/release behavior; it does not cover
   every collection page or constitute a physical-device test.

   Acceptance: add screen-touch interaction for every menu action and
   combined joystick/skill/pause input, then validate browser/mobile behavior.

4. **Long-running rain and round experience need direct scenarios.**
   The food audit's isolated 75-second no-consumption rain scenario exposes a
   24-body admission stall not rejected by the existing short rain checks.
   The ordinary auto-route finishes with only 3 of 136 buildings consumed.
   Existing full-scene tests deliberately center and resize the hole for
   every item (`tests/full_city_qa_acceptance.gd:41`), which proves focused
   admission and falls but not ordinary route pacing or player understanding.

   Acceptance: maintain rain under no-consumption and partial-consumption
   scenarios, track landed/airborne bodies separately, and review normal
   unassisted rounds for variety and sustained visible collapses.

## Evidence limits

The authorized browser inventory returned `User unavailable` again. No native
foreground window, alternate browser connection, screen capture workaround or
fabricated gameplay screenshot was used. Existing 2D layout reconstructions
may illustrate control placement but omit all 3D game views. The earlier
windowless mesh fixtures are also not gameplay screenshots.

The three agent probes run in isolated `--test` sessions. Their measurements
must be read with their declared simulation conditions. In particular, a
stationary no-consumption rain test is a reproducible feature stress case,
and an automatic route is not a claim about human completion time. No new
absolute performance measurement is made while agents run concurrently.
